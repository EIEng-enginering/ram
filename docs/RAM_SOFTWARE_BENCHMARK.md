# RAM software benchmark · 20 November 2026

This is a desk review of public product documentation, manuals and author-published technical metadata. It covers directly relevant production and RAM tools plus adjacent benchmarks. It excludes undocumented features from scoring and makes no performance or superiority claim. No licensed product was installed or tested.

## Design and acceptance priorities

1. **Time to a reviewable model.** Measure time from an input pack to the first editable, evidence-linked graph. Count equipment/edge precision and recall against an engineer-established reference. Report errors and justified abstentions independently.
2. **Time to a defensible comparison.** Measure time from an engineering question to a repeatable scenario comparison. Preserve approved inputs, configuration differences, comparable random streams where appropriate and confidence in the difference.
3. **Clarity of model display.** From a production-loss result, an engineer should be able to open the event timeline and identify the bottleneck, resource wait or buffer boundary, then inspect the basis for the associated model assumptions.
4. **Report review effort.** Track quantitative claims with and without source/run references, conflicts caught before release and the engineering time required to complete approval. Every accepted numeric claim comes from the run record through a stable reference.
5. **Engineering validity.** Compare the synthetic cases against algebra/Markov and hand-calculated capacity cases. Compare external examples only where inputs and reporting definitions are disclosed. Benchmark both common small models and large models, recording environment, run settings and time.
